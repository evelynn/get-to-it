# 결함 제거 (공통, 한국어)

get-to-it(답변·보고서)과 long-form(긴 글·윤문·번역)의 공통 진단표. 목적: 목적과 내용을 정확하고 명확하게 전달. 결함은 네 가지: 뜻이 달라짐, 무슨 말인지 안 보임, 번역한 글처럼 읽힘, AI가 쓴 글처럼 읽힘.

## 적용 원칙

- 금지어 없음. 패턴은 어색한 원인을 찾는 단서. 그 자리에서 자연스러우면 유지. "통해", "제공", "진행", "관련하여"도 맞는 자리에서는 평범한 한국어.
- 문단 단위로 판단. 한두 번 쓴 표현은 유지, 한 문단에 몰릴 때만 축소.
- 정확성이 다듬기보다 우선. 고치면 뜻이 달라지는 문장은 원문 유지.
- 맞는 격식어를 짧은 구어로 교체 금지. "품질 관리에 중점을 두었습니다"와 "품질 관리에 집중했습니다"는 다른 뜻.
- 의학·법률·정책·계약 문장의 유보 표현과 승인된 문구는 유지.
- 고치면서 새 결함 추가 금지(새 비유, 새 대비, 새 인과).
- 보고체로 쓴 글(답변, 업무 보고서, 새로 쓰는 긴 글)은 명사형 종결과 불릿이 정상. 4절의 리듬·불릿 항목 미적용.

## 1. 뜻이 달라짐

원문과 대화에 있는 그대로 유지.

- 코드, 명령, 경로, 식별자, 자리표시자, 오류 원문, 직접 인용
- 수치와 측정 조건, 날짜·시각·시간대·마감, 금액·통화·할인과 조건
- 제품·요금제·브랜드·사람 이름, 굳은 업계 용어
- 계약·자격·한도, 환불·교환·배송·취소 정책, 보증 범위와 예외
- 부정, 예외, "만·최대·약·미만" 같은 한정어
- 확신 정도. 가능성을 약속으로, 확정을 가능성으로 변경 금지
- 요청·제안·약속의 구분, 완료 상태, 책임 주체, 결정 이유

추가 금지: 원문에 없는 사실, 수치, 혜택, 성능 주장, 후기, 긴박감, 사과, 감사, 약속, 원인.

- 점검만 한 일을 결함 발견처럼 기재 금지. "로그 확인 완료"와 "로그에서 오류 발견" 구분.
- 함께 일어났을 뿐인 두 일을 "그래서"로 잇기 금지. "어제 안내문을 수정했습니다. 오늘 문의가 줄었습니다."는 두 사실로 유지.
- 문장을 합쳐도 사실마다 상태·조건·시점이 따로 읽혀야 함. "베타 버전으로 변경될 수 있습니다"는 지금 베타인지 베타로 바뀐다는 것인지 불명 → 현재 상태와 앞으로의 변화를 분리.
- 경계값 유지. "10분 미만"을 "10분 안에"로 쓰면 10분 포함 → "10분도 걸리지 않습니다".
- 빈 값은 지어내지 않고 `[보증 기간]` 같은 자리표시로 유지.

## 2. 무슨 말인지 안 보임

| 결함 | 고침 | 둘 때 |
| --- | --- | --- |
| 행위자가 명사 속에 숨음: "요청이 이루어졌다", "검토가 진행되었다" | 행위자를 주어로, 행동을 동사로: "고객이 요청했다", "법무팀이 검토했다" | 원문에 행위자 없음(지어내기 금지). 보고체 명사형 종결 |
| 조사 없이 명사 4개 이상: "데이터베이스 준비 상태 확인 위치" | 조사를 살리거나 동사로 풀기: "데이터베이스가 준비됐는지 확인하는 곳" | 굳은 복합어("고객 만족도 조사") |
| 그 분야에서 안 쓰는 단어 조합: "세션 진입 경계", "효과 귀속" | 실제로 쓰는 말이나 코드의 실제 이름: "로그인 처리 직전", "`authMiddleware()` 호출 전" | 자주 쓰는 회사어("정합성 확보"), 업계 용어 |
| 대상이 둘 이상이거나 없는 지칭: "이것", "해당", "위 문제" | 대상을 다시 기재 | 바로 앞의 대상 하나를 가리킴 |
| 요점이 끝에 묻힌 문장, 지워도 잃는 정보가 없는 문장 | 요점을 앞으로, 빈 문장 삭제 | - |
| 가리키는 것 없는 추상어와 기준 없는 평가: "방향성·측면·관점", "전략적·효과적·혁신적", "다양한", "의미 있는" | 그 말이 가린 결정·행동·항목·확인된 결과 기재 | 그 개념이 분석 대상. 원문에 근거나 기준 있음 |
| 한쪽이 빠진 비교와 확인: "어긋남", "문제가 있다", "꼼꼼히 확인했다" | 무엇과 무엇이 달랐는지, 무엇을 어떻게 확인했는지 기재. 원문에 없으면 좁게 유지 | 앞뒤 문장에서 이미 분명 |
| 출처 없는 주어·평가: "전문가들은", "업계에서는", "~다는 분석이다" | 받은 출처 기재 또는 주장 범위 축소. 출처 지어내기 금지 | 앞뒤에 출처 있음 |
| 제목을 되풀이하는 자기소개: "이 화면은 ~하는 화면입니다". 확인할 수 없는 "한눈에" | 보이는 항목과 상태 기재 | 제목에 없는 범위·제약·대상을 더함 |

추상어를 다른 추상어로 교체 금지. "품질 게이트를 고도화했다"를 "품질 기준을 고도화했다"로 바꿔도 막연함. 실제 규칙이나 점검 내용 기재.

## 3. 번역한 글처럼 읽힘

| 패턴 | 고침 | 둘 때 |
| --- | --- | --- |
| 도구·장소·행동에 붙은 "~를 통해" | "~로", "~에서", 행동을 동사로: "분석을 통해 확인했다" → "분석해 확인했다" | 경로·매개가 요점. 공지의 굳은 표현("홈페이지를 통해 안내드립니다") |
| 행동 대상 앞의 "~에 대해", "~에 대한" | "을/를" 직결: "오류에 대해 분석했다" → "오류를 분석했다" | 행동 대상이 아닌 화제 제시 |
| "~에 있어서", "~에서의", "~와 관련하여", "~을 바탕으로" | "~에서", "~은/는", "~로", 절로 풀기: "서버에서의 처리" → "서버에서 처리할 때" | 범위·법적 관계 표시. 공지 제목("배송 지연 관련 안내") |
| "가지고 있다", "보유하고 있다" | "있다", "갖췄다", 형용사: "강한 경쟁력을 가지고 있다" → "경쟁력이 강하다" | 법적 소유·자산 보유가 정확한 뜻 |
| 행위자를 아는 "~에 의해", 이중 피동 "~되어진다" | 행위자를 주어로: "스크립트가 만든 파일". 단일 피동: "판단된다" | 행위자를 모르거나 일부러 밝히지 않음 |
| 끝난 행동의 "~하게 되었다" | 행동 그대로: "연락드리게 되었습니다" → "연락드립니다" | 실제 전환, 외부 원인, 통제 밖 변화 |
| 사람이 하는 일의 "~이 가능합니다", "~이 불가합니다" | "~할 수 있습니다", "~할 수 없습니다" | 표·라벨·보고체("당일 배송 불가", "적용 가능") |
| 이중 부정: "~가 아닌 한 ~할 수 없습니다" | "~인 경우에만 ~할 수 있습니다" | 승인된 법률 문구. 예외 목록이 긴 경우 |
| 한 번에 끝나는 일의 "진행·수행": "설치를 진행해 주세요" | "설치해 주세요" | 여러 단계 과정. 진행 상태("환불이 진행 중입니다") |
| 기능마다 붙는 "~을 제공합니다", "~하는 역할을 합니다" | 독자가 얻는 것·할 수 있는 일: "값을 반환합니다" | 회사가 실제로 주는 서비스·혜택("무료 배송을 제공합니다") |
| 추상 주어 + "보여준다·가져온다·만든다" | 사람·기관을 주어로. "~ 때문에", "~에 따르면" | - |
| 영어에서 넘어온 대명사: "당신", "그것", "우리는", 반복되는 "귀하의" | 행위자를 알 수 있을 때만 생략. 행위자가 바뀌면 다시 기재하거나 "고객님", "회원님", 브랜드명 사용 | 공문·법률 고지의 "귀하". 대비에 필요한 주어 |
| 영어 관용구 직역과 사전식 번역어: "연락을 취하다", "게임 체인저", "구현 지원" | 원문이 뒷받침하는 동작, 그 업계 실무 용어: "연락드립니다", "도입 지원" | 그 분야 독자가 이미 쓰는 말 |
| 명사 앞의 긴 수식절, 명사화 누적(-성·-적·-화): "전략적 함의" | 문장 분리, 동사·형용사로 풀기 | 정의된 용어 |
| 분열문: "필요한 것은 재시작입니다", "원인은 캐시라는 것입니다" | 주어와 서술어 직결: "재시작해야 합니다", "원인은 캐시입니다" | 여러 항목 중 하나를 짚는 문장 |
| 의례적 서두: "다름이 아니오라", "~에 대해 말씀드리고자 연락드리게 되었습니다" | 연락 이유와 요청부터 기재 | 관계상 의례가 필요한 공식 서한 |
| "~하도록 하겠습니다" | 말하는 사람이 직접 하는 확정 약속이면 "~하겠습니다" | 다른 사람이 하게 하는 뜻, 노력만 약속하는 뜻. 약속 강도 변경 금지 |
| 번역식 명령형: "지금 구매하세요!", "시작하세요" | 버튼은 "구매하기", "무료로 시작하기". 본문은 "~해 보세요"나 평서문 | 원문에 있는 마감·긴박감은 유지. 없는 것은 추가 금지 |

한 글 안에서 어체 혼용 금지. 원문의 격식을 평어로 낮추거나 "-했-"을 "-하였-"으로 높이기 금지.

## 4. AI가 쓴 글처럼 읽힘

- 결산·의의: "결론적으로", "종합하면", "이를 통해", "시사하는 바가 크다", "중요한 역할을 한다" → 삭제하고 마지막 사실이나 원문이 뒷받침하는 결과 기재. 결과가 원문에 없으면 빈 주장 삭제.
- 강조용 대비: "단순한 X를 넘어 Y", "X가 아니라 Y", "더 이상 ~이 아니다" → Y를 바로 기재. 실제 오해를 바로잡는 대비는 유지, 한 글에 한 번.
- 결말 공식: "~할 때입니다", "~하는 이유입니다", "X에서 Y로의 전환", "과제도 남아 있다" → 구체적 사실·조건으로 교체. 원문에 없는 시점 지어내기 금지.
- 열거 예고: "다음과 같습니다", "크게 세 가지로 나눌 수 있습니다" → 예고 없이 본론. 억지 3개 나열은 원문이 뒷받침하는 개수만.
- 비유·과장: "청사진", "신호탄", "적신호", "발목을 잡다", "판도를 바꾼다", "압도적인" → 실제로 한 일과 사실 그대로. 뜻이 불명확하면 원문 유지.
- 대상만 바꿔 반복하는 범용 동사(확대·강화·개선·확보·마련·구축) → 실제로 한 행동의 동사.
- 겹친 완곡과 사과: "~할 가능성이 있을 수 있다", 겹친 "죄송합니다" → 원문 강도로 하나만. 단정 전환 금지.
- 서식: 이모지, 문장 속 굵은 글씨, 강조용 따옴표, 설명을 붙이는 대시, 반복되는 괄호 영어 병기 → 삭제. 영어 병기는 처음 한 번.
- 리듬: 모든 문장·불릿이 같은 길이와 같은 어미 → 관련 있는 것은 합치고 넘치는 것은 분리. 리듬 때문에 내용 추가 금지.
- 이어지는 설명을 불릿 조각으로 쪼갬 → 문단으로 작성. 나열이 뜻인 곳만 불릿.

## 5. 외래어·내부 용어

- 그 분야 독자가 쓰는 말은 유지: 표준 용어(API, prompt, token, commit), 고객이 쓰는 외래어(포인트, 쿠폰, 리뷰, 구독, 노쇼), 제품이 이미 쓰는 용어.
- 일반 독자 대상 글에서만 내부 용어 풀이: 컨텍스트 → 맥락·조건, 케이스 → 경우, 이슈 → 문제, 플로우 → 흐름·절차, 리스크 → 위험, 게이트 → 통과 조건, 회귀 → 기존 기능 동작 변경.
- 필요한 전문 용어는 처음 한 번 풀이. 같은 개념은 같은 용어로 통일.

## 6. 문단 흐름·문장부호

- 줄이기 전에 문단으로 읽기. 다음 문장이 앞 문장을 보충하는지, 대비하는지, 이유를 대는지 확인.
- 연결어는 원문이 뒷받침하는 관계에만 사용. 인과("그래서", "-아서")는 원문이 원인을 말할 때만. 대비("하지만", "-지만")는 실제 대비일 때만. 순서("이후", "-한 뒤")를 인과로 변경 금지. "-면서"는 동시에 일어나는 일에만.
- 줄이면서 원인·대비·순서·지시를 잇는 말 삭제 금지. 짧아져도 독자가 관계를 다시 짜 맞춰야 하면 실패.
- 토막 난 문장 나열 금지. 주어와 생각이 같은 짧은 문장은 연결어미로 연결: "자료를 확인했습니다. 그리고 표를 고쳤습니다. 그리고 보냈습니다." → "자료를 확인하고 표를 고친 뒤 보냈습니다." 다른 접속사로 돌려 막기 금지.
- 독립된 불릿, UI 라벨, 일부러 끊은 대화에는 연결어 추가 금지.
- 연결어미(-고·-며·-지만·-면서·-아서·-는데) 바로 뒤 쉼표 삭제. 영어식 쉼표 휴지도 삭제. 범위 표시와 양식이 요구하는 부호는 유지.
