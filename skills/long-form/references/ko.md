# 한국어 긴 글·윤문·번역

같은 스킬 `SKILL.md`의 규칙에 더해 한국어 글에만 적용하는 기준. 결함 진단은 `shared/defects.ko.md` 사용. 어체는 이 문서 1절이 `SKILL.md`보다 우선.

목표: 한국 독자가 회사에서 처음부터 한국어로 쓴 글로 읽는 글. 뜻 보존이 다듬기보다 우선.

## 1. 어체

| 상황 | 어체 |
| --- | --- |
| 새로 쓰는 글(문서, README, 메일, 공지, 안내문) | 회사어투 보고체. 명사형 종결("~함", "~예정", "~필요", "~완료"), "~합니다"·"~해요" 미사용 |
| 사용자가 어체를 지정한 글 | 지정한 어체 |
| 윤문 | 원문의 격식 |
| 번역, 번역 대조 | 원문의 격식에 대응하는 어체 |
| 버튼, 제목, 배너, 사양표 | 명사구 |

- 새로 쓰는 글의 어체 변경은 사용자가 따로 요청할 때만("합쇼체로", "고객 안내문 어투로", 양식·예시 제공). 독자나 매체를 보고 임의로 변경 금지.
- 결과물에 붙이는 설명과 질문도 보고체로 작성("[이름] 기재 필요", "포털 사외 접속 가능 여부 확인 요청").
- 보고체 메일·공지는 "안녕하세요", "~입니다" 같은 인사말과 맺음말 없이 제목과 첫 줄에 용건 기재.
- 보고체 긴 글은 제목과 불릿으로 구성, 불릿 하나에 사실 하나. 어미만 보고체, 단어는 회사에서 실제로 쓰는 쉬운 말. 뜻이 흐려지게 압축 금지, 명사 4개 이상 연속 금지. 완료·진행 중·미확인 상태 구분.
- 번역에서 단서가 없을 때 대응 어체: B2B 메일·계약·공지는 합쇼체, 소비자 앱 문장은 해요체. 기존 한국어 문구나 브랜드 예시가 있으면 그쪽 적용. 이미 일관된 글을 기본값 때문에 변경 금지.

## 2. 영어 → 한국어

- 한국어로 먼저 쓴 글처럼 문장 구성. 영어 문장 경계, 단어 대응, 기계 번역 초안과의 유사도는 목표 아님.
- 호칭: 업무 메일에서 이름만 부르기 금지. 맥락에 있는 성명과 직함("김지연 매니저님") 또는 회사와 직함 사용.
- 변수와 조사: `{name}과`처럼 값의 받침에 따라 바뀌는 조사는 틀릴 수 있음. 변수 뒤에 명사를 붙이거나("{project_name} 프로젝트와") 받침과 무관한 말("{name}님") 사용.
- 버튼: 결과가 안 보이는 "확인" 대신 하는 동작 기재("삭제", "구매하기").
- 범위가 달라지는 번역어 주의. "ship" → "출고"("배송"은 도착 약속으로 읽힘). "automates"를 "완전 자동화"로 강화 금지.
- 날짜와 금액은 한국식 표기 가능("5만 원", "12월 15일").
- 혜택은 조건·마감과 붙여서 기재("5만 원 이상 주문 시 무료 배송 (제주 및 도서산간 지역 제외)"). "최대", "약", "기준" 유지.

## 3. 고침 예

윤문·번역 예시라 원문 격식을 유지한 결과. 정답 문구가 아니라 판단 기준이며 같은 사실·조건·격식을 지키면 다른 표현도 통과.

| 원문 | 결과 | 이유 |
| --- | --- | --- |
| "귀하의 팀이 최근 세 개의 새로운 창고를 오픈했다는 것을 보고 연락드리게 되었습니다." | "최근 창고 세 곳을 새로 여셨다는 소식을 보고 연락드립니다." | 영어 어순, 반복되는 "귀하의", 끝난 행동의 "~게 되었습니다" |
| "환불은 배송일로부터 7일 이내에 앱 내 채팅을 통해서만 요청이 가능합니다." | "환불은 상품을 받은 날부터 7일 이내에 앱 채팅으로만 신청할 수 있습니다." | 사람이 하는 일의 "가능합니다". "만" 한정은 유지 |
| "현재 계약은 3월 31일에 종료됩니다. 같은 조건으로 갱신을 원하시면 3월 15일까지 알려 주세요." | 그대로 반환 | 이미 자연스러운 글. 고치면 위험만 추가 |
| "사용 시간: 최대 120분 (에코 모드 기준)" | 그대로 반환 | 사양표는 명사구가 정상. "최대", "기준"이 조건을 전달 |
| "5월 8일까지 도착하지 않을 경우 회신해 주시면 즉시 환불해 드리겠습니다." (영어 원문은 "we'll look into it") | "5월 8일까지 받지 못하시면 이 메일에 회신해 주세요. 확인해 드리겠습니다." + 차이 한 줄 고지 | 원문에 없는 환불 약속 삭제 |
| 본문 "{project_name}과 해당 파일이 삭제됩니다.", 버튼 "확인" (영어 원문은 영구 삭제, 팀 전체, 복구 불가 명시) | 본문 "{project_name} 프로젝트와 프로젝트 안의 모든 파일이 팀 전체에서 영구 삭제됩니다. 삭제한 후에는 되돌릴 수 없습니다.", 버튼 "삭제" | 빠진 결과 복원, 받침에 따라 틀리는 조사 제거, 버튼에 동작 기재 |
| "어제 안내문을 수정했습니다. 오늘 문의가 줄었습니다." | 그대로 반환 | "그래서"를 넣으면 원문에 없는 인과 발생 |

## 4. 추가 점검

`SKILL.md`의 최종 점검에 더해 확인.

1. 새로 쓴 글은 보고체인지, 윤문·번역은 원문 격식 그대로인지, 한 글에 어체가 섞이지 않았는지
2. 연결어미 뒤 쉼표가 원문보다 늘지 않았는지
