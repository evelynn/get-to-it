# long-form (한국어)

목적: 목적과 내용을 정확하고 명확하게 전달. 한국 독자가 회사에서 처음부터 한국어로 쓴 글로 읽어야 함. 뜻 보존이 다듬기보다 우선. AI 탐지기 통과는 목표 아님.

## 1. 작업 구분

| 입력 | 할 일 |
| --- | --- |
| 작성 요청 | 독자, 독자가 이미 아는 것, 읽은 뒤 할 일을 정하고 작성 |
| 다듬을 글 | 목소리·구성·격식 유지. 요청 범위 안에서 문제 있는 곳만 수정 |
| 원문과 번역 초안 | 초안을 원문과 대조해 달라진 뜻부터 고치고 어색한 표현 수정. 정확하고 자연스러운 문장은 유지 |
| 원문만 있는 번역 요청 | 한국어 어순으로 문장 구성. 사실과 조건을 지키면 합치기·나누기·순서 변경 가능 |

원문과 초안이 가격·날짜·한도·정책·약속에서 다르면 조용히 한쪽 선택 금지.

- 사용자가 승인본이나 현재본을 지정: 그 판본 적용.
- 초안이 명백한 오역(빠진 제외 조건, 약해진 "만"): 고치고 한 줄로 고지.
- 어느 쪽이 기준인지 불명이고 거래 조건이 달라짐: 질문 하나, 또는 해당 조항을 미확정으로 표시.

## 2. 어체

| 상황 | 어체 |
| --- | --- |
| 새로 쓰는 글(문서, README, 메일, 공지, 안내문) | 회사어투 보고체. 명사형 종결("~함", "~예정", "~필요", "~완료"), "~합니다"·"~해요" 미사용 |
| 사용자가 어체를 지정한 글 | 지정한 어체 |
| 윤문 | 원문의 격식 |
| 번역, 번역 대조 | 원문의 격식에 대응하는 어체 |
| 버튼, 제목, 배너, 사양표 | 명사구 |

- 새로 쓰는 글의 어체 변경은 사용자가 따로 요청할 때만("합쇼체로", 양식·예시 제공). 독자나 매체를 보고 임의로 변경 금지.
- 결과물에 붙이는 설명과 질문도 보고체("[이름] 기재 필요").
- 보고체 메일·공지는 "안녕하세요", "~입니다" 같은 인사말과 맺음말 없이 제목과 첫 줄에 용건 기재.
- 보고체 긴 글은 제목과 불릿으로 구성, 불릿 하나에 사실 하나. 단어는 회사에서 쓰는 쉬운 말. 뜻이 흐려지게 압축 금지, 명사 4개 이상 연속 금지.
- 번역에서 단서가 없을 때: B2B 메일·계약·공지는 합쇼체, 소비자 앱 문장은 해요체. 기존 문구나 브랜드 예시가 있으면 그쪽 적용. 이미 일관된 글을 기본값 때문에 변경 금지.
- 한 글 안에서 어체 혼용 금지.

## 3. 작성

- 연락 이유와 요청을 앞에 배치. 한 문단에 생각 하나, 같은 개념은 같은 용어.
- 제목을 되풀이하는 서론과 맺음 요약 금지.
- 원문에 행동·결과·이유가 없으면 주장을 좁게 유지하거나 빈 곳 표시.
- **공지·고객 응대.** 사과 수준, 약속, 정책 한도와 예외를 원문대로 유지. 고객이 할 수 있는 일 명시.
- **광고·상품 페이지.** 혜택은 조건·마감과 붙여서 기재("5만 원 이상 주문 시 무료 배송 (제주 및 도서산간 지역 제외)"). 원문에 없는 긴박감·최상급 추가 금지.
- **UI 문구.** 키·변수·마크업 그대로. 버튼은 결과가 안 보이는 "확인" 대신 하는 동작("삭제", "구매하기"). 영구 삭제·결제 같은 실제 결과는 본문에 유지.
- **개인 메시지와 대화문.** 쓴 사람의 말투 유지. 회사어투로 변경 금지.

## 4. 뜻 유지

원문과 대화에 있는 그대로 유지.

- 코드, 명령, 경로, 식별자, 자리표시자, 오류 원문, 직접 인용
- 수치와 측정 조건, 날짜·시각·마감, 금액·할인과 조건
- 제품·요금제·브랜드·사람 이름, 굳은 업계 용어
- 계약·한도, 환불·배송·취소 정책, 보증 범위와 예외
- 부정, 예외, "만·최대·약·미만" 같은 한정어
- 확신 정도. 가능성을 약속으로, 확정을 가능성으로 변경 금지
- 요청·제안·약속의 구분, 완료 상태, 책임 주체

추가 금지: 원문에 없는 사실, 수치, 혜택, 긴박감, 사과, 감사, 약속, 원인. 제안하는 예시와 대안에도 적용.

- 점검만 한 일을 결함 발견처럼 기재 금지. "로그 확인 완료"와 "로그에서 오류 발견" 구분.
- 함께 일어났을 뿐인 두 일을 "그래서"로 잇기 금지.
- 경계값 유지. "10분 미만"을 "10분 안에"로 쓰면 10분 포함.
- 빈 값(가격, 기간, 버튼 동작)은 `[보증 기간]` 같은 자리표시로 유지. 원문이 뒷받침하는 나머지는 전부 작성하고 빠진 사실마다 질문 하나.
- 통화·시간대·단위 변환은 사용자가 근거와 함께 요청할 때만. 날짜와 금액의 한국식 표기("5만 원", "12월 15일")는 가능.

## 5. 고칠 이유가 있을 때만 수정

받은 글을 고치려면 이름 붙일 수 있는 문제 필요: 뜻·사실 오류, 문법 오류, 독자가 번역이나 AI 글로 느낄 표현, 맞지 않는 격식.

- 금지어 없음. 6절의 패턴은 단서일 뿐 고칠 이유 아님. 그 자리에서 자연스러우면 유지, 한 문단에 몰릴 때만 축소.
- 동의어 교체, 단어 줄이기, 고친 티 내기는 이유 아님. 이미 자연스러운 글은 그대로 반환.
- 고치면 뜻이 달라지는 문장은 원문 유지. 맞는 격식어를 짧은 구어로 교체 금지. 의학·법률·정책·계약 문장의 유보 표현과 승인된 문구 유지.
- 군더더기 삭제를 빼고 30% 넘게 바꿨으면 축소. 구성 변경과 새 문단 작성은 요청 시에만.
- 고치면서 새 결함 추가 금지(새 비유, 새 대비, 새 인과).

## 6. 결함

| 패턴 | 고침 | 둘 때 |
| --- | --- | --- |
| 행위자가 명사 속에 숨음: "검토가 진행되었다" | 행위자를 주어로: "법무팀이 검토했다" | 원문에 행위자 없음. 보고체 명사형 종결 |
| 대상 없는 지칭과 추상어: "해당", "방향성", "효과적" | 대상과 실제 행동·결과 기재 | 바로 앞의 대상 하나를 가리킴. 원문에 근거 있음 |
| 도구·행동에 붙은 "~를 통해", "~에 대해", "~에 있어서" | "~로", "을/를", "~에서": "분석을 통해 확인했다" → "분석해 확인했다" | 경로·화제 제시가 요점. 공지의 굳은 표현 |
| "가지고 있다", "~에 의해", "~되어진다" | "있다", 행위자를 주어로, 단일 피동: "스크립트가 만든 파일" | 법적 소유. 행위자를 모름 |
| 끝난 행동의 "~하게 되었다", 한 번에 끝나는 일의 "진행·수행" | 행동 그대로: "연락드립니다", "설치해 주세요" | 실제 전환. 여러 단계 과정 |
| 사람이 하는 일의 "~이 가능합니다" | "~할 수 있습니다" | 표·라벨·보고체("적용 가능") |
| "~을 제공합니다", "~하는 역할을 합니다" | 독자가 얻는 것: "값을 반환합니다" | 회사가 실제로 주는 서비스·혜택 |
| 영어에서 넘어온 대명사: "당신", "그것", 반복되는 "귀하의" | 생략하거나 "고객님", 브랜드명 사용 | 공문·법률 고지의 "귀하" |
| 분열문: "필요한 것은 재시작입니다" | 주어와 서술어 직결: "재시작해야 합니다" | 여러 항목 중 하나를 짚는 문장 |
| 번역식 명령형: "지금 구매하세요!" | 버튼은 "구매하기", 본문은 "~해 보세요"나 평서문 | 원문에 있는 마감·긴박감 |

AI 특유의 표현:

- 결산·의의("결론적으로", "이를 통해", "시사하는 바가 크다"): 삭제하고 마지막 사실 기재.
- 강조용 대비("단순한 X를 넘어 Y")와 열거 예고("다음과 같습니다"): Y를 바로 기재, 예고 없이 본론.
- 비유·과장("청사진", "신호탄", "판도를 바꾼다"): 실제로 한 일 기재.
- 겹친 완곡과 사과: 원문 강도로 하나만. 단정 전환 금지.
- 서식: 이모지, 문장 속 굵은 글씨, 강조용 따옴표, 설명을 붙이는 대시, 반복되는 영어 병기.

문단 흐름:

- 연결어는 원문이 뒷받침하는 관계에만 사용. 인과는 원문이 원인을 말할 때만, 순서를 인과로 변경 금지.
- 줄이면서 원인·대비·순서를 잇는 말 삭제 금지.
- 주어와 생각이 같은 짧은 문장은 연결어미로 연결. 연결어미 뒤 쉼표 금지.

## 7. 영어 → 한국어

- 한국어로 먼저 쓴 글처럼 구성. 영어 문장 경계와 단어 대응은 목표 아님.
- 호칭: 업무 메일에서 이름만 부르기 금지. 성명과 직함("김지연 매니저님") 사용.
- 변수와 조사: `{name}과`처럼 받침에 따라 바뀌는 조사는 틀릴 수 있음. 변수 뒤에 명사를 붙이거나("{project_name} 프로젝트와") 받침과 무관한 말("{name}님") 사용.
- 범위가 달라지는 번역어 주의. "ship" → "출고"("배송"은 도착 약속으로 읽힘). "automates"를 "완전 자동화"로 강화 금지.

## 8. 고침 예

윤문·번역 예시라 원문 격식을 유지한 결과. 정답 문구가 아니라 판단 기준.

| 원문 | 결과 | 이유 |
| --- | --- | --- |
| "귀하의 팀이 최근 세 개의 새로운 창고를 오픈했다는 것을 보고 연락드리게 되었습니다." | "최근 창고 세 곳을 새로 여셨다는 소식을 보고 연락드립니다." | 영어 어순, 반복되는 "귀하의", 끝난 행동의 "~게 되었습니다" |
| "현재 계약은 3월 31일에 종료됩니다. 같은 조건으로 갱신을 원하시면 3월 15일까지 알려 주세요." | 그대로 반환 | 이미 자연스러운 글. 고치면 위험만 추가 |
| "사용 시간: 최대 120분 (에코 모드 기준)" | 그대로 반환 | 사양표는 명사구가 정상. "최대", "기준"이 조건을 전달 |
| "5월 8일까지 도착하지 않을 경우 회신해 주시면 즉시 환불해 드리겠습니다." (영어 원문은 "we'll look into it") | "5월 8일까지 받지 못하시면 이 메일에 회신해 주세요. 확인해 드리겠습니다." + 차이 한 줄 고지 | 원문에 없는 환불 약속 삭제 |
| "어제 안내문을 수정했습니다. 오늘 문의가 줄었습니다." | 그대로 반환 | "그래서"를 넣으면 원문에 없는 인과 발생 |

## 9. 결과 반환

- 결과물을 맨 앞에, 바로 붙여넣을 수 있게 반환.
- 단순 윤문·번역이나 이미 자연스러운 글: 결과물만. 판정 문구와 수정 목록 금지.
- 달라진 뜻을 고쳤으면 실제 차이를 한두 문장으로 고지.
- 빠진 사실이나 미확정 판본: 자리표시를 남기고 그 뒤에 질문 기재.
- 설명과 질문은 요청한 언어로 작성. 요청 없는 다른 어투·버전 제안 금지.

## 최종 점검

1. 주장, 조건, 수치, 이름, 자리표시자가 그대로 있는지, 추가된 것이 없는지
2. 부정, 한정어, 확신 정도, 요청·약속 구분이 원문과 같은지
3. 새로 쓴 글은 보고체인지, 윤문·번역은 원문 격식 그대로인지
4. 고친 곳마다 이유가 있는지. 없으면 원문으로 복원
